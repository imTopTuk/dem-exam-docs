### Виртуализация и гипервизоры

Виртуализация — запуск нескольких изолированных ОС на одном физическом сервере. Слой между железом и ВМ — **гипервизор**. Он распределяет CPU, RAM, диски и сеть между гостевыми системами.

| Тип | Название          | Где работает            | Примеры                     |
| --- | ----------------- | ----------------------- | --------------------------- |
| 1   | bare-metal        | прямо на железе         | VMware ESXi, Proxmox (KVM), Hyper-V, XCP-ng |
| 2   | hosted            | поверх ОС хоста         | VirtualBox, VMware Workstation |
| —   | контейнеризация   | общее ядро              | Docker, LXC (не полноценная ВМ) |

Для серверов используют **гипервизор 1-го типа** — меньше накладных расходов и выше плотность ВМ.

### Ресурсы виртуальной машины

- **vCPU** — виртуальные процессоры; сумма vCPU по ВМ может превышать физические ядра (overcommit), но растёт конкуренция;
- **RAM** — выделяется жёстко или динамически (ballooning, memory overcommit);
- **Диск** — виртуальный: `qcow2`/`raw` (KVM), `vmdk` (VMware), `vhdx` (Hyper-V);
- **Снапшот** — снимок состояния на момент времени; **не** заменяет резервную копию (растёт цепочка, падает производительность);
- **Клонирование** — полный или связанный клон (linked clone) от базового образа.

Практика: ставить **гостевые дополнения** (virtio/QEMU-agent/guest-tools) — иначе нет нормальной производительности и корректного завершения.

### Виртуальные сети

| Режим сети        | Что даёт                                             |
| ----------------- | ---------------------------------------------------- |
| Bridge            | ВМ — «полноценный» узел в физической сети            |
| NAT               | ВМ за адресом хоста (аналог домашней сети)           |
| Host-only         | изолированная сеть: ВМ ↔ хост                        |
| Internal/Private  | только между ВМ, без выхода                          |

В гипервизорах 1-го типа сети строят **виртуальными коммутаторами** (vSwitch): порты — access/trunk, VLAN-теги, агрегация. Диски и сеть подключают через паравиртуализированные драйверы (virtio/net) — быстрее эмулированных.

<span style="color: 00cc18">Ключевые команды (Proxmox/KVM):</span>

- `qm list`, `qm start/stop 100`, `qm config 100` — управление ВМ;
- `virsh list --all`, `virsh start vm1`, `virsh console vm1` — через libvirt;
- `qemu-img info/convert` — работа с дисками ВМ;
- `ip -br link show` + `bridge link` — проверка мостов/vSwitch.

### Типичные ошибки на экзамене:

- снапшоты держат месяцами вместо бэкапов — цепочка диска растёт, ВМ «тормозит»;
- overcommit по RAM без учёта — OOM убивает ВМ;
- ВМ без гостевых дополнений — нет выключения по ACPI, кривые драйверы;
- забыли про **MTU и VLAN** на виртуальном коммутаторе — трафик ВМ не ходит;
- один физический хост — единая точка отказа (нет кластера/HA);
- не изолирована management-сеть гипервизора от гостевых сетей;
- привязка ВМ к локальному хранилищу — не поднять на другом узле.
