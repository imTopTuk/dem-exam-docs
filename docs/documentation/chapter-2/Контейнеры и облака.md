# Контейнеры и облака

Docker, оркестрация, IaaS/PaaS/SaaS
### Контейнеры и облака

**Контейнер** — изолированный процесс с собственным окружением, использующий **общее ядро** хоста. Легче виртуальной машины: быстрый старт, меньше накладных расходов, но слабее изоляция (нет своего ядра).

| Сравнение | ВМ | Контейнер |
| --------- | -- | --------- |
| Ядро      | своё | общее с хостом |
| Запуск    | десятки секунд | доли секунды |
| Размер    | гигабайты | мегабайты |
| Изоляция  | сильная | на уровне процессов/namespaces |

### Docker

Основные понятия:

- **образ (image)** — неизменяемый шаблон (слои), собирается из `Dockerfile`;
- **контейнер** — запущенный экземпляр образа;
- **том (volume)** — постоянное хранилище данных (вне контейнера);
- **сеть** — bridge (по умолчанию), host, overlay;
- **registry** — хранилище образов (Docker Hub, приватный registry).

<span style="color: 00cc18">Ключевые команды:</span>

- `docker build -t app:1.0 .`, `docker run -d -p 8080:80 --name app app:1.0`;
- `docker ps -a`, `docker logs app`, `docker exec -it app bash`;
- `docker volume create data`, `docker network create net`;
- `docker compose up -d` — запуск группы сервисов из `docker-compose.yml`.

Правила образов: **не хранить секреты** в образе, не запускать от root, маленькие базовые образы (`alpine`), фиксировать теги (не `latest`).

### Оркестрация

Когда контейнеров много, нужна оркестрация — автоматический запуск, масштабирование, самовосстановление:

- **Kubernetes** — стандарт: pod, deployment, service, ingress, configmap/secret;
- **Docker Swarm**, **Nomad** — проще;
- **Helm** — пакеты для k8s;
- **CI/CD** собирает образ, сканирует, и выкладывает его в среду.

### Облачные модели

| Модель | Кто управляет              | Пример                     |
| ------ | -------------------------- | -------------------------- |
| IaaS   | провайдер — железо; клиент — ОС/приложения | виртуальные серверы, диски, сети |
| PaaS   | провайдер — платформа; клиент — код | managed БД, app-платформы |
| SaaS   | провайдер — всё; клиент — использует | почта, офис, CRM        |

Развёртывание: **публичное**, **приватное**, **гибридное** облако. В РФ — реестр отечественного ПО и локальные (on-prem) решения.

### Типичные ошибки на экзамене:

- хранят данные **внутри контейнера** — при пересоздании всё теряется, нужен том;
- секреты запекают в образ — утечка через registry;
- используют тег `latest` — невоспроизводимые развёртывания;
- запускают контейнеры от root и с `--privileged` — слабая изоляция;
- публикуют порт наружу без необходимости вместо внутренней сети;
- путают резервное копирование тома и снапшот контейнера;
- забывают обновлять базовые образы — тянут уязвимости;
- в продакшене один Docker-хост без резервирования — единая точка отказа.
