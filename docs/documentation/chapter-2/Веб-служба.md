# Веб-служба

Apache/Nginx, виртуальные хосты, TLS, reverse proxy
### Веб-служба

Веб-сервер отдаёт клиентам статику и (через модуль/fastcgi) динамику, принимает запросы по **HTTP/HTTPS**. Два популярных сервера:

| Сервер | Сильная сторона |
| ------ | --------------- |
| Apache | модульность, `.htaccess`, прост для классических CMS |
| Nginx  | высокая нагрузка, статика, **reverse proxy** и балансировка |

### Виртуальные хосты

Один сервер обслуживает много сайтов по **имени** (Name-based, по заголовку `Host`) или по IP (IP-based).

- **Nginx**: `server { listen 80; server_name site.ru; root /var/www/site; }` в `sites-available` + симлинк в `sites-enabled`;
- **Apache**: `<VirtualHost *:80> ServerName site.ru DocumentRoot /var/www/site </VirtualHost>`;
- **Документрут** — каталог сайта; индексные файлы (`index.html`/`index.php`);
- проверка: `nginx -t`, `apachectl configtest`; перезапуск `systemctl reload nginx`.

### Динамика и права

- **PHP-FPM** через fastcgi (Nginx) или `mod_php` (Apache);
- для PHP-приложений права каталогов — владелец `www-data`, без 777;
- виртуальные каталоги/алиасы могут указывать вне document root — следить за безопасностью;
- **логи**: `access.log` (кто и что), `error.log` (ошибки);
- **производительность**: `worker_processes`, `worker_connections`, кэш статики, gzip/brotli.

### TLS и HTTPS

1. сгенерировать **ключ и CSR**: `openssl req -new -newkey rsa:2048 -nodes -keyout site.key -out site.csr`;
2. получить сертификат (CA или самоподписанный: `openssl req -x509 ...`);
3. подключить в конфиге:

```
listen 443 ssl;
ssl_certificate     /etc/nginx/ssl/site.crt;
ssl_certificate_key /etc/nginx/ssl/site.key;
ssl_protocols TLSv1.2 TLSv1.3;
```

- `Let's Encrypt`/`certbot` — автоматические сертификаты (ACME), но домен должен резолвиться;
- обязателен **HTTP→HTTPS redirect**; HSTS (по желанию);
- проверка цепочки: `openssl s_client -connect site.ru:443 -servername site.ru`.

### Reverse proxy

Nginx/Apache принимает внешний запрос и передаёт на внутренний сервер приложения:

```
location /api/ {
  proxy_pass http://127.0.0.1:8080;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}
```

Даёт: единый вход, TLS-терминация, балансировку (`upstream`), кэш, сокрытие бэкендов, защиту от прямого доступа к приложению.

### Типичные ошибки на экзамене:

- `server_name` не совпадает с DNS-именем — отдаётся сайт по умолчанию;
- симлинк из `sites-available` в `sites-enabled` не создан — сайт не работает;
- права на документрут `777` или владелец root — дыра в безопасности;
- сертификат на другое имя (CN/SAN) — браузер ругается;
- `ssl_certificate_key` с неправильными правами (нужно `600`, владелец сервиса);
- забыли открыть **80/443** в файрволе;
- reverse proxy теряет реальный IP клиента (нет `X-Forwarded-For`) — логи и фильтры врут;
- забыли `proxy_set_header Host` — бэкенд отдаёт редиректы на localhost.
