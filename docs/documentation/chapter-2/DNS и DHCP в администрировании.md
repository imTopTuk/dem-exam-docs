### DNS и DHCP в администрировании

Базовые сведения о DNS и DHCP — в главе 1; здесь — их совместная эксплуатация.

### Связка DNS + DHCP

Сервисы работают в паре: **DDNS** позволяет DHCP-серверу самому регистрировать адрес клиента в DNS, чтобы имена появлялись без ручной правки зон.

- в Windows: DHCP шлёт `dynamic updates` на DC-DNS (Secure only);
- в BIND: ключи TSIG + `allow-update` для зоны;
- обратные (PTR) зоны обновляются так же — важно для PTR-проверок сервисов.

### Зоны и делегирование

- **прямая зона** — имена → IP (`A`), **обратная** — IP → имена (`PTR`);
- **делегирование** — передача поддомена на другой сервер через **NS**-записи;
- **зональный трансфер** — репликация зоны на вторичный сервер: `AXFR`/`IXFR` (TCP/53);
- **stub/CNAME/forward zone** — варианты организации пространства имён;
- **split-brain (views)** — внутренние и внешние ответы на один домен разными зонами (BIND `view`).

### Релей DHCP

Клиент рассылает DHCP-broadcast в своей подсети, а сервер может стоять централизованно:

- на шлюзе включают **DHCP relay** (`ip helper-address` на Cisco, `dhcrelay` на Linux, `/ip dhcp-relay` на MikroTik);
- опция **82** (relay agent info) сообщает серверу, из какого порта/VLAN пришёл запрос — выдача адресов по расположению.

### Интеграция с Active Directory

- зона DNS хранится **в базе AD** (AD-integrated) → репликация средствами AD, безопасные динамические обновления;
- **SRV-записи** (`_ldap._tcp.dc._msdcs...`) — основа поиска служб домена;
- DHCP **авторизуется в AD** от имени администратора — защита от rogue-DHCP;
- DHCP/DNS серверы поднимают на контроллерах или выделенных узлах.

<span style="color: 00cc18">Диагностика:</span>

- `dig SOA/NS zone`, `dig +short srv1`, `dig -x 192.168.1.20`;
- `named-checkzone`, `rndc reload`, `dnscmd`/`Get-DnsServerZone`;
- на клиенте: `ipconfig /all`, `ipconfig /registerdns`, `dhclient -r/-v`;
- `ss -lunp | grep :53`, `dhcpd -t`, `journalctl -u isc-dhcp-server`.

### Типичные ошибки на экзамене:

- сервер и клиенты в разных подсетях, **relay не настроен** — DHCP не проходит;
- DDNS не включён — свежие адреса не резолвятся, старые записи «залипают»;
- обратная зона не обновляется — сервисы, требующие PTR, не работают;
- два DHCP-сервера на одну подсеть без разделения диапазонов — конфликты;
- зональный трансфер открыт всем (`allow-transfer any`) — утечка зоны;
- split-brain настроен с ошибкой — наружу «светится» внутренняя зона;
- неверный часовой пояс/время → сорванные подписи DDNS (TSIG) и AD;
- забыли, что DHCP-сервер в AD нужно **авторизовать**.
