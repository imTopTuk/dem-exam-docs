# Промышленный Ethernet

PROFINET, EtherNet/IP, EtherCAT, реальное время
### Промышленный Ethernet

Промышленный Ethernet — обычный Ethernet (IEEE 802.3), адаптированный к цеху: помехозащищённые разъёмы (M12, RJ45 с фиксацией), расширенный температурный диапазон, устойчивость к вибрациям. Главное отличие от офисного — **детерминизм** (предсказуемое время доставки).

### Режимы реального времени

| Класс | Название        | Применение                   |
| ----- | --------------- | ---------------------------- |
| —     | best effort     | офисный Ethernet              |
| soft  | мягкое РВ       | HMI, счётчики (доли секунды)  |
| hard  | жёсткое РВ      | сервоприводы, синхронизация (микросекунды) |

Жёсткое РВ требует приоритизации: **IEEE 802.1Q (PCP)**, **802.1p**, и часто — специальных механизмов (например, суммирующего кадра у PROFINET IRT).

### Основные протоколы

| Протокол  | Стандарт/базис | Особенность                              |
| --------- | -------------- | ---------------------------------------- |
| PROFINET  | IEC 61158      | RT/IRT, основа Siemens, цикл обмена данными |
| EtherNet/IP | CIP over TCP/UDP | CIP-объекты, основа Rockwell/Allen-Bradley |
| EtherCAT  | IEC 61158      | «на лету», топология линия/кольцо, очень малое время цикла |
| Modbus TCP| простая надстройка | простой запрос/ответ, распространён |
| POWERLINK | Ethernet Powerlink | изохронный обмен                 |

### Мастер/слейв и цикл обмена

В обмене есть **master** (контроллер) и **slaves** (устройства). Мастер циклически посылает и собирает данные процесса (input/output), обеспечивая детерминированный обмен. Параметры: **время цикла**, **watchdog**, **device diagnosis**.

### Топологии

- **линия/шина** — просто, но кольцо надёжнее;
- **звезда** — через коммутаторы;
- **кольцо** — резервирование (см. MRP/RSTP);
- смешанные — на практике.

### Типичные ошибки на экзамене:

- ставят на магистраль **неуправляемый** коммутатор — нет приоритетов и диагностики;
- смешивают трафик hard-RT с офисным (broadcast, обновления) в одной среде;
- превышают время цикла из-за длинной линии/лишних устройств;
- путают физический Ethernet и протокол прикладного уровня (PROFINET vs Ethernet);
- нет резервирования линии — обрыв останавливает участок;
- используют офисные разъёмы в цехе (вибрация, пыль, влага);
- игнорируют диагностику устройств (device diagnosis) — отказ не виден заранее;
- неправильный **кабель/экранирование** — помехи и ошибки CRC.
