# Сегментация и защита промышленных сетей

зоны/уровни, DMZ, NGFW, шлюзы
### Сегментация и защита промышленных сетей

АСУ ТП нельзя изолировать «наглухо» — нужны обмен с MES/ERP и удалённое обслуживание. Задача — соединить уровни **безопасно**, по модели **IEC 62443**.

### Зоны и каналы (IEC 62443)

- **зона** — группа активов с общими требованиями безопасности (уровень Purdue);
- **канал (conduit)** — контролируемый путь между зонами (правила файрвола);
- между уровнями 2 и 3/4 — **DMZ** и **промышленный файрвол**;
- принцип: сегментировать по уровням и функциям, минимизировать связи.

### Промышленный межсетевой экран (NGFW)

- контролирует **трафик по прикладным протоколам** (Modbus, OPC UA, PROFINET), а не только порты;
- разрешает только нужные функции/регистры (deep packet inspection);
- поддерживает **односторонний шлюз (data diode)** там, где данные идут только в одну сторону;
- ведёт журнал и обнаруживает аномалии;
- ставится в разрыв между OT и IT/DMZ.

### Удалённый доступ в АСУ ТП

- только через **выделенный шлюз** и после аутентификации (VPN с MFA);
- сессии регистрируются, доступ — по заявке и на время;
- техническое обслуживание — не «напрямую», а через jump-host/DMZ.

### Коммутационные запреты и практики

- запрещены **неуправляемые** соединения OT↔IT;
- USB/съёмные носители — только через проверку;
- отдельные контуры для обновлений и резервного копирования;
- baseline-конфигурации и контроль изменений;
- резервное копирование конфигураций ПЛК/SCADA — и их проверка.

### Типичные ошибки на экзамене:

- подключают локальную АСУ ТП к интернету «для удалённого доступа» без шлюза;
- используют офисный файрвол только по портам, без понимания протоколов АСУ ТП;
- один плоский OT-VLAN на всё производство;
- правило «any → any» внутри OT;
- нет журналирования и контроля сессий вендора;
- доверяют «изолированной» сети, хотя есть носители и ноутбуки;
- обновления/антивирусы льют из корпоративной сети в OT;
- нет плана на случай отказа шлюза/DMZ.
