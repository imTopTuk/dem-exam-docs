# Маршрутизация

Статические маршруты, OSPF (метрики, MD5-аутентификация)
### Маршрутизация

Маршрутизация — выбор пути для пакета между сетями по **таблице маршрутизации**. Решение принимается по правилам, строго по порядку:

1. **Longest prefix match** — побеждает самый длинный совпавший префикс (например, `/24` важнее `/8`);
2. **Административное расстояние (AD)** — доверие к источнику маршрута (у разных протоколов своё);
3. **Метрика** — «стоимость» пути внутри одного протокола; меньше — лучше.

#### Административное расстояние (Cisco)

| Источник маршрута      | AD  |
| ---------------------- | --- |
| Connected (directly)   | 0   |
| Static                 | 1   |
| eBGP                   | 20  |
| OSPF                   | 110 |
| RIP                    | 120 |
| iBGP                   | 200 |
| Недостоверный (крайний) | 255 |

#### Состав строки маршрута

Сеть/префикс → next-hop (шлюз) или выходной интерфейс → метрика → AD. Маршрут по умолчанию — это `0.0.0.0/0` (совпадает со всем, но только если нет более длинного совпадения).

### Статическая маршрутизация

Статический маршрут задаёт администратор вручную. Плюсы: предсказуемость, минимум нагрузки, безопасность. Минусы: не подстраивается под аварии, плохо масштабируется.

<span style="color: 00cc18">Ключевые команды:</span>

- **Cisco**: `ip route 192.168.20.0 255.255.255.0 10.0.0.2` — маршрут через next-hop; `ip route 192.168.20.0 255.255.255.0 gi0/0` — через интерфейс (только для p2p);
- `ip route 0.0.0.0 0.0.0.0 10.0.0.1` — маршрут по умолчанию;
- `ip route 192.168.20.0 255.255.255.0 10.0.0.2 200` — **floating static** (AD=200): резерв, включится, если основной маршрут исчезнет;
- **Linux**: `ip route add 192.168.20.0/24 via 10.0.0.2`; по умолчанию — `ip route add default via 10.0.0.1`;
- **MikroTik**: `/ip route add dst-address=192.168.20.0/24 gateway=10.0.0.2`;
- **FRR**: `ip route 192.168.20.0/24 10.0.0.2`.

Проверка: `show ip route` (Cisco), `ip route` / `ip -br route` (Linux), `traceroute` / `tracert`.

### Динамическая маршрутизация и OSPF

Динамические протоколы сами обмениваются информацией о сетях. OSPF (Open Shortest Path First) — **link-state** IGP: каждый роутер строит карту топологии (LSDB) и считает кратчайшие пути алгоритмом Дейкстры (SPF).

#### Термины и структура

- **Area** — области; обязательна **backbone area 0**, все остальные области подключаются к ней (напрямую или через virtual-link);
- **Neighbor / Adjacency** — соседство устанавливается через Hello-пакеты;
- **DR/BDR** — выделенные роутеры на широковещательном сегменте (снижают число соседств);
- **Router-ID** — уникальный идентификатор роутера (обычно старший loopback-адрес);
- **LSA** — описания топологии, которые рассылают роутеры.

#### Метрика (cost)

Стоимость интерфейса: **cost = reference bandwidth / bandwidth интерфейса**, округление вниз, минимум 1. По умолчанию reference = 100 Мбит/с, поэтому уже на гигабите cost = 1 и дальше не различается — на практике reference повышают.

<span style="color: 00cc18">Ключевые команды OSPF (Cisco):</span>

- `router ospf 1` — включить процесс;
- `router-id 1.1.1.1` — задать Router-ID;
- `network 10.0.0.0 0.0.0.255 area 0` — включить интерфейсы в OSPF (маска — **wildcard**, инверсия);
- `interface gi0/0` → `ip ospf cost 10` — задать cost вручную;
- `interface gi0/0` → `ip ospf priority 0` — не участвовать в выборах DR/BDR;
- `passive-interface gi0/1` — не рассылать Hello в «клиентскую» сеть;
- `show ip ospf neighbor`, `show ip ospf interface`, `show ip route ospf`.

<span style="color: 00cc18">MD5-аутентификация OSPF:</span>

- `interface gi0/0` → `ip ospf message-digest-key 1 md5 P@ssw0rd` — ключ с номером (key-id) на интерфейсе;
- в процессе: `area 0 authentication message-digest` — требовать аутентификацию в области;
- ключ должен совпадать у обоих соседей; иначе соседство не поднимется (`show ip ospf neighbor` — пусто, в логах `MD5 authentication failed`).

<span style="color: 00cc18">FRR / MikroTik:</span>

- **FRR** (`vtysh`): `router ospf` → `ospf router-id 1.1.1.1`, `network 10.0.0.0/24 area 0`; аутентификация на интерфейсе: `ip ospf authentication message-digest`, `ip ospf message-digest-key 1 md5 P@ssw0rd`;
- **MikroTik**: `/routing ospf instance`, `/routing ospf area`, `/routing ospf interface-template add networks=10.0.0.0/24 area=backbone` + параметры аутентификации.

#### Типичные ошибки на экзамене:

- в `network` указывают маску подсети, а не **wildcard-маску** (нужно `0.0.0.255`, а не `255.255.255.0`);
- не совпадают **area**, **hello/dead-таймеры** или **MTU** — соседство не поднимается;
- разный ключ/номер MD5 у соседей — adjacencies падают;
- забыли **area 0** или область не подключена к ней — маршруты не распространяются;
- не задан Router-ID или он дублируется — нестабильный SPF;
- все интерфейсы активные, включая клиентские: `passive-interface` не поставлен, лишний трафик и соседства;
- cost не пересчитывают при высоких скоростях (reference bandwidth забыли повысить) — маршрут выбирается «по-старому»;
- статический резервный маршрут добавляют с AD=1 — он не сработает как резерв, нужен больший AD (floating static).
