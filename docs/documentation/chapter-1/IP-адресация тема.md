# IP-адресация тема

Расчет подсетей (VLSM), приватные диапазоны, маски
### IP-адресация (IPv4)

IPv4-адрес — 32-битное значение, записываемое в точечно-десятичной нотации (4 октета). Адрес состоит из двух частей: идентификатор сети и идентификатор хоста. Граница между ними задаётся маской подсети.

В современных сетях используется бесклассовая адресация (CIDR, RFC 4632), поэтому границу определяет префикс, а не класс адреса (A/B/C).

#### Маска подсети

Маска — 32-битное число, где единицы обозначают сетевую часть, а нули — хостовую. Префикс `/n` указывает количество единичных бит.

<span style="color: 00cc18">Ключевые формулы:</span>

- Всего адресов в подсети: **2^(32−n)**
- Доступных хостов: **2^(32−n) − 2**
- Адрес сети: побитовое AND адреса и маски
- Широковещательный адрес: адрес сети с хостовой частью, заполненной единицами

Исключение: на `/31` (RFC 3021) используются оба адреса для point-to-point-каналов, на `/32` — один адрес (loopback, host route).

| Префикс | Маска           | Адресов | Хостов |
| ------- | --------------- | ------- | ------ |
| /24     | 255.255.255.0   | 256     | 254    |
| /25     | 255.255.255.128 | 128     | 126    |
| /26     | 255.255.255.192 | 64      | 62     |
| /27     | 255.255.255.224 | 32      | 30     |
| /28     | 255.255.255.240 | 16      | 14     |
| /29     | 255.255.255.248 | 8       | 6      |
| /30     | 255.255.255.252 | 4       | 2      |

### Приватные диапазоны (RFC 1918)

| Диапазон                               | Префикс        | Применение       |
| -------------------------------------- | -------------- | ---------------- |
| Класс А: 10.0.0.0 – 10.255.255.255     | 10.0.0.0/8     | крупные сети     |
| Класс B: 172.16.0.0 – 172.31.255.255   | 172.16.0.0/12  | средние сети     |
| Класс C: 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 | малые офисы, дом |

### VLSM (Variable Length Subnet Mask)

VLSM — техника разбиения адресного пространства на подсети **разной длины префикса** в рамках одной сети. Позволяет экономно использовать адреса: каждая подсеть получает размер, соответствующий реальной потребности.

#### Алгоритм расчёта:
1. Составить список требований (число хостов в каждой подсети), отсортировать по убыванию.
2. Для каждой подсети найти минимальный n, при котором 2^n − 2 ≥ N хостов, префикс = 32 − n.
3. Выделять блоки последовательно, начиная с большего. Начало каждого блока должно быть кратно его размеру (выравнивание по границе).
4. Проверить отсутствие пересечений и достаточность исходного блока

**Пример.** Исходная сеть `192.168.1.0/24`, требования: отдел А — 100 хостов, отдел Б — 50 хостов, p2p-канал между маршрутизаторами — 2 адреса.

[Нейрохрючевый пример тут](Нейрохрючевый пример тут.md)

|Подсеть|Нужно|Префикс|Адрес сети|Диапазон хостов|Broadcast|
|---|---|---|---|---|---|
|Отдел А|100|/25|192.168.1.0|.1 – .126|.127|
|Отдел Б|50|/26|192.168.1.128|.129 – .190|.191|
|Канал R1–R2|2|/30|192.168.1.192|.193 – .194|.195|

#### Типичные ошибки на экзамене:
- не сортируют подсети по убыванию и получают пересечения или нехватку места;
- забывают вычесть 2 (адрес сети и broadcast);
- начинают блок не на границе своего размера (например, `/26` с адреса `.100`);
- путают маску и wildcard-маску (в ACL и OSPF используется инверсия: `0.0.0.255`).
