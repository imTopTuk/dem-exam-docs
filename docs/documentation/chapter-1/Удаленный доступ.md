# Удаленный доступ

SSH (смена порта, запрет root, ограничение попыток, баннеры)
### Удалённый доступ

Удалённый доступ — управление узлом по сети без физического присутствия. Базовые протоколы:

| Протокол | Порт | Безопасность                     |
| -------- | ---- | -------------------------------- |
| Telnet   | 23   | **нет**: логин/пароль открытым текстом |
| SSH      | 22   | шифрование, аутентификация        |
| RDP      | 3389 | шифрование, но привязан к Windows |
| VNC      | 5900 | слабое шифрование/его отсутствие |

**SSH (Secure Shell)** — стандарт: шифрует канал, умеет пароли и ключи, туннели и проброс портов. Telnet в продакшене не используют.

### Аутентификация

- **по паролю** — просто, но уязвимо к перебору;
- **по ключу** — пара «приватный/публичный»: на сервер кладут публичный ключ, приватный хранится у клиента.
  - `ssh-keygen -t ed25519 -C "user@host"` — создать пару;
  - `ssh-copy-id user@host` — скопировать публичный ключ на сервер (`~/.ssh/authorized_keys`).

В конфиге сервера `/etc/ssh/sshd_config` можно **запретить пароли** (`PasswordAuthentication no`) и оставить только ключи.

### Базовое усиление SSH (hardening)

<span style="color: 00cc18">Ключевые директивы sshd_config:</span>

| Директива             | Значение          | Зачем                              |
| --------------------- | ----------------- | ---------------------------------- |
| `Port`                | 2222              | сменить порт (сброс шума ботов)     |
| `PermitRootLogin`     | no                | запрет входа root напрямую          |
| `MaxAuthTries`        | 3                 | ограничение попыток пароля          |
| `LoginGraceTime`      | 30                | время на аутентификацию             |
| `AllowUsers`          | admin             | белый список входов                 |
| `PasswordAuthentication` | no             | только ключи                        |
| `PermitEmptyPasswords`| no                | запрет пустых паролей               |
| `Banner`              | /etc/issue.net    | баннер-предупреждение                |
| `Protocol`            | 2                 | только SSHv2                        |

После правок — проверить конфиг и перезапустить:

- `sshd -t` — синтаксис;
- `systemctl restart sshd` (или `ssh`);
- **важно:** не закрывать текущую сессию, пока не проверен вход новой — иначе можно потерять доступ.

<span style="color: 00cc18">Баннеры:</span>

- текст в `/etc/issue.net` (для SSH) и `/etc/issue` (для локальной консоли);
- в `sshd_config`: `Banner /etc/issue.net`;
- баннер с предупреждением о запрете несанкционированного доступа — требование многих чек-листов.

### Файрвол и защита от перебора

- ограничить доступ по IP: `nft`/`iptables`/`firewalld`, `ufw allow from 192.168.1.0/24 to any port 2222`;
- **fail2ban**: читает логи SSH и временно банит IP после N неудач (`/etc/fail2ban/jail.local`, `[sshd]`, `maxretry`, `bantime`);
- ограничение частоты подключений в `iptables` (`-m recent`/`limit`).

### Сетевое оборудование и прочее

- **Cisco**: `username admin secret ...`, `ip domain-name example.local`, `crypto key generate rsa modulus 2048`, `line vty 0 4` → `login local`, `transport input ssh`, `exec-timeout 5 0`;
- **MikroTik**: `/ip service disable telnet,ftp`; `/user add name=admin ...`; доступ по ключам в `/user ssh-keys`;
- **Windows**: OpenSSH-сервер или RDP; RDP не выставляют в интернет напрямую (только через VPN/шлюз).

**VPN для удалённого доступа** (когда нужно «как в офисе»): WireGuard, OpenVPN, IPsec/IKEv2, L2TP/IPsec. Сначала VPN-туннель, затем внутрь — SSH/RDP, а наружу открывают только VPN-порт.

#### Типичные ошибки на экзамене:

- смену порта SSH делают **без** правки правил файрвола/SELinux — доступ теряется;
- оставляют `PermitRootLogin yes` и вход по паролю — прямой путь к брутфорсу;
- задают `AllowUsers`, забыв себя/нужного пользователя — блокируют доступ;
- перезапускают sshd, не проверив `sshd -t` — служба не поднимается, доступ потерян;
- хранят приватный ключ без пароля и с правами 644 (нужно `600`, `.ssh` — `700`);
- путают `/etc/ssh/ssh_config` (клиент) и `/etc/ssh/sshd_config` (сервер);
- выставляют RDP/Telnet напрямую в интернет вместо VPN;
- баннер забыли — не проходит проверка по чек-листу безопасности.
