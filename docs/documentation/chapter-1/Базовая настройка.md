# Базовая настройка

hostname, FQDN, синхронизация времени (NTP/Chrony)
### Имя хоста (hostname)

Hostname — сетевое имя узла, по которому его узнают в сети, логах и служебных сервисах. Правила (RFC 1123): до **63 символов**, только латиница, цифры и дефис; не начинается и не заканчивается дефисом; регистр не важен (приводится к нижнему).

Различают три вида имени:

| Вид          | Что это                                         | Где хранится                    |
| ------------ | ----------------------------------------------- | ------------------------------- |
| static       | постоянное имя, применяется при загрузке        | `/etc/hostname`                 |
| transient    | текущее имя в ядре (до перезагрузки)            | память, команда `hostname`      |
| pretty       | «человеческое» имя для отображения              | `hostnamectl`, может быть любым |

<span style="color: 00cc18">Ключевые команды:</span>

- `hostnamectl set-hostname srv1.example.local` — задать **постоянное** имя (systemd);
- `hostname` — показать текущее; `hostname newname` — задать **временно** (сбросится после перезагрузки);
- `hostnamectl status` — сразу показывает все три имени и часовой пояс;
- файлы: `/etc/hostname` — имя узла, `/etc/hosts` — статическая таблица «IP → имя».

### FQDN (Fully Qualified Domain Name)

FQDN — полное доменное имя узла вида `хост.домен.зона`, например `srv1.example.local`. Состоит из меток, разделённых точками: каждая метка ≤ 63 символов, всё имя ≤ **253 символов**. Завершающая точка — корень зоны (в записях DNS), обычно опускается.

Разрешение имени идёт по порядку из `/etc/nsswitch.conf`:

1. `/etc/hosts` — статическая таблица (обычно приоритетнее);
2. DNS — динамическое разрешение: **A-запись** — прямая (имя → IP), **PTR** — обратная (IP → имя).

<span style="color: 00cc18">Ключевые команды:</span>

- `hostname -f` — FQDN, `hostname -s` — короткое имя, `hostname -d` — домен;
- `host srv1.example.local`, `dig`, `nslookup` — проверка разрешения через DNS;
- `getent hosts srv1` — проверка через **реально используемый** источник (hosts/DNS), а не только DNS.

Пример записи в `/etc/hosts`:

```
127.0.1.1   srv1.example.local   srv1
```

FQDN должен совпадать с PTR-записью и с именем сервиса в прикладных настройках (Kerberos, сертификаты, почта). Иначе — ошибки аутентификации и «недоверенные» сертификаты.

### Синхронизация времени

Зачем нужна: корректные метки времени в логах, проверка TLS-сертификатов, Kerberos (расхождение больше **5 минут** — отказ аутентификации), работа БД и кластеров, корреляция событий при разборе инцидентов.

#### NTP и уровни (stratum)

NTP (Network Time Protocol) — протокол синхронизации времени, работает по **UDP/123**. Узлы делятся на уровни:

| Stratum | Кто это                                        |
| ------- | ---------------------------------------------- |
| 0       | эталон: атомные часы, GPS, аппаратный источник |
| 1       | сервер, подключённый к эталону напрямую        |
| 2       | клиент stratum 1, который раздаёт время дальше |
| …       | каждый следующий уровень — «дальше» от эталона |
| 16      | время не синхронизировано                      |

Чем меньше stratum, тем ближе узел к эталону. Stratum — это не «точность», а «удалённость» от источника.

#### Chrony

Chrony — современная реализация NTP (замена ntpd). Быстрее первичная синхронизация, стабильнее при больших задержках и в виртуальных машинах — поэтому в ВМ часто используют именно её. Два компонента:

- `chronyd` — демон, который держит время;
- `chronyc` — консольный клиент управления.

Конфигурация: `/etc/chrony.conf` (в Debian/Ubuntu — `/etc/chrony/chrony.conf`).

<span style="color: 00cc18">Ключевые параметры chrony.conf:</span>

- `pool ntp.example.ru iburst` — пул внешних серверов;
- `server 192.168.1.1 iburst` — конкретный сервер (например, шлюз/контроллер домена);
- `driftfile /var/lib/chrony/drift` — файл учёта дрейфа часов;
- `allow 192.168.1.0/24` — **кому** этот узел разрешает брать у него время (режим сервера);
- `local stratum 10` — работать как источник, если внешних серверов нет (изолированная сеть);
- `makestep 1.0 3` — при большом расхождении первые 3 подстройки делать скачком.

<span style="color: 00cc18">Ключевые команды chronyc:</span>

- `chronyc sources -v` — список источников и их состояние (`^*` — текущий, `^+` — резервный, `^?` — недоступен);
- `chronyc tracking` — насколько узел синхронизирован, какая задержка и stratum;
- `chronyc makestep` — принудительно подтянуть время скачком;
- `systemctl enable --now chronyd` — включить и запустить службу.

#### Клиент и сервер

- **Клиент** берёт время у серверов (`pool`/`server`).
- **Сервер** дополнительно раздаёт время: добавляет `allow <сеть>` и, если внешних источников нет, `local stratum 10`, чтобы сеть могла синхронизироваться автономно.
- Открыть в файрволе **UDP/123**, иначе синхронизация не заработает.

#### Часовой пояс и аппаратные часы

- `timedatectl` — показать время, RTC, статус NTP и часовой пояс;
- `timedatectl set-timezone Europe/Moscow` — задать пояс;
- `timedatectl set-ntp true` — включить синхронизацию;
- `hwclock -w` — записать системное время в аппаратные часы (RTC);
- часовой пояс хранится в `/etc/localtime` (ссылка) и `/etc/timezone`; на серверах RTC обычно держат в **UTC**.

#### Другие системы (кратко)

- Windows: служба W32Time — `w32tm /config /manualpeerlist:"pool.ntp.org" /syncfromflags:manual /update`, `w32tm /resync`;
- MikroTik: `/system ntp client set enabled=yes servers=...`, `/system clock set time-zone-name=Europe/Moscow`.

#### Типичные ошибки на экзамене:

- расхождение времени больше 5 минут — падают Kerberos и TLS, аутентификация не проходит;
- `allow` без указания сети или `allow 0.0.0.0/0` — отдают время кому угодно;
- забыли открыть **UDP/123** — синхронизации нет;
- у виртуальных машин время «дрейфует»: нужен внешний источник, а не надежда на гипервизор;
- путают stratum с точностью и ждут «точнее» от меньшего номера любой ценой;
- задают имя только командой `hostname` — после перезагрузки оно пропадает (нет записи в `/etc/hostname`);
- FQDN не совпадает с PTR-записью — ломаются сервисы, завязанные на обратное разрешение;
- меняют часовой пояс, не перезапуская завязанные службы, и получают «сдвинутые» логи и сертификаты.
