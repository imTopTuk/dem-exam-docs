# Служба DHCP

Настройка пулов, исключений, опций (шлюз, DNS, суффикс)
### Служба DHCP

DHCP (Dynamic Host Configuration Protocol) автоматически выдаёт хостам сетевые параметры: IP-адрес, маску, шлюз, DNS и др. Работает по **UDP/67** (сервер) и **UDP/68** (клиент). Убирает ручную настройку и конфликты адресов.

#### Процесс DORA

| Шаг | Пакет               | Смысл                                     |
| --- | ------------------- | ----------------------------------------- |
| D   | DHCP Discover       | клиент broadcast-ом ищет сервер           |
| O   | DHCP Offer          | сервер предлагает адрес и параметры       |
| R   | DHCP Request        | клиент запрашивает конкретное предложение |
| A   | DHCP Acknowledgment | сервер подтверждает и фиксирует аренду    |

После выдачи запись хранится в таблице аренд (**lease**). По умолчанию клиент продлевает её на 50 % срока (**T1**), затем на 87.5 % (**T2**); если не успел — запрашивает заново. Если сервер недоступен, клиент берёт адрес из **APIPA** (169.254.0.0/16).

### Настройка пулов

**Пул (scope)** — диапазон выдаваемых адресов в одной подсети. Ключевые элементы:

- **range** — диапазон адресов для выдачи;
- **exclusions** — адреса, исключённые из выдачи (шлюз, серверы, оборудование со статикой);
- **reservations** — жёсткая привязка по MAC (сервер или принтер всегда получает свой адрес);
- **options** — параметры, передаваемые клиенту.

#### Основные опции

| Код | Опция                     | Пример        |
| --- | ------------------------- | ------------- |
| 3   | Router (шлюз по умолчанию) | 192.168.1.1  |
| 6   | DNS-серверы                | 192.168.1.10 |
| 15  | Domain name (суффикс)      | example.local |
| 42  | NTP-серверы                | 192.168.1.10 |
| 51  | Lease time                 | 86400         |
| 150 | TFTP/доп. серверы          | —             |

<span style="color: 00cc18">Ключевые команды (isc-dhcp-server, `/etc/dhcp/dhcpd.conf`):</span>

```
subnet 192.168.1.0 netmask 255.255.255.0 {
  range 192.168.1.100 192.168.1.200;
  option routers 192.168.1.1;
  option domain-name-servers 192.168.1.10;
  option domain-name "example.local";
  default-lease-time 86400;
  max-lease-time 172800;
}
host printer {
  hardware ethernet AA:BB:CC:DD:EE:FF;
  fixed-address 192.168.1.50;
}
```

- сервер слушает нужный интерфейс: `INTERFACESv4="eth0"` в `/etc/default/isc-dhcp-server`;
- проверка конфига: `dhcpd -t`; аренды: `/var/lib/dhcp/dhcpd.leases`;
- **dnsmasq** проще для small-office: строки `dhcp-range`, `dhcp-option=3,...`, `dhcp-option=6,...`;
- **Kea** — современная замена isc-dhcp (конфиг в JSON).

<span style="color: 00cc18">Cisco / MikroTik:</span>

- **Cisco**: `ip dhcp pool LAN` → `network 192.168.1.0 255.255.255.0`, `default-router 192.168.1.1`, `dns-server 192.168.1.10`, `domain-name example.local`; исключения — `ip dhcp excluded-address 192.168.1.1 192.168.1.99`;
- **MikroTik**: `/ip pool add name=lan ranges=192.168.1.100-192.168.1.200`; `/ip dhcp-server add interface=bridge address-pool=lan`; `/ip dhcp-server network add address=192.168.1.0/24 gateway=192.168.1.1 dns-server=192.168.1.10 domain=example.local`.

### DHCP-релей (relay)

DHCP-broadcast не проходит через маршрутизатор, поэтому, если сервер в другой подсети, на шлюзе включают **relay**:

- **Cisco**: `interface gi0/1` → `ip helper-address 192.168.1.10` (адрес DHCP-сервера);
- **Linux**: `dhcrelay -i eth0 -i eth1 192.168.1.10` (пакет `isc-dhcp-relay`);
- **MikroTik**: `/ip dhcp-relay add interface=... dhcp-server=192.168.1.10`.

Опция **82** (relay agent information) позволяет серверу различать, из какой подсети/порта пришёл запрос — удобно для выдачи адресов по VLAN.

#### Типичные ошибки на экзамене:

- **Диапазон пула включает адрес шлюза/сервера** — конфликт адресов; нужны exclusions;
- сервер и клиенты в **разных VLAN**, а `ip helper-address` не настроен — DHCP не доходит;
- не указан `domain-name` (опция 15) — FQDN и суффикс у клиентов неверные;
- неверные DNS/шлюз в опциях — «интернет не работает», хотя адрес выдан;
- слишком короткий **lease** — частые продления и нагрузка; слишком длинный — адреса не освобождаются;
- сервер слушает не тот интерфейс (`INTERFACESv4`) — запросы не принимаются;
- один диапазон выдан двумя DHCP-серверами без согласования — коллизии;
- гостевая/серверная сеть не изолированы от общего пула.
