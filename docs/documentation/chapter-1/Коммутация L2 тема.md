# Коммутация L2 тема

VLAN, Access/Trunk порты, Router-on-a-Stick
### VLAN (Virtual LAN)

VLAN — логическая сеть внутри одного физического коммутатора или группы коммутаторов. Устройства одного VLAN общаются на канальном уровне напрямую, даже если физически подключены к разным портам; между VLAN нужен маршрутизатор (L3). VLAN решает три задачи: **сегментация** широковещательного домена, **изоляция** трафика и **гибкость** (абонент переезжает — VLAN не меняется).

Каждый VLAN имеет **VID** (VLAN ID), диапазон 1–4094:

| VID            | Обозначение | Назначение                          |
| -------------- | ----------- | ----------------------------------- |
| 1              | default     | VLAN по умолчанию, обычно не трогают |
| 2–1001         | normal      | обычные VLAN                        |
| 1002–1005      | reserved    | служебные (Token Ring/FDDI)         |
| 1006–4094      | extended    | расширенные VLAN                     |

#### IEEE 802.1Q

Стандарт тегирования кадров в транке. В кадр вставляется **4-байтный тег** между полями Source MAC и EtherType:

| Поле        | Биты | Смысл                                   |
| ----------- | ---- | --------------------------------------- |
| TPID        | 16   | `0x8100` — признак 802.1Q                |
| Priority    | 3    | PCP, приоритет QoS (0–7)                 |
| DEI/CFI     | 1    | отбрасывание/формат                      |
| **VID**     | 12   | номер VLAN (до 4094)                     |

Вместо EtherType 802.1Q существует **QinQ (802.1ad)** — два тега (внешний + внутренний) для операторских сетей.

#### Native VLAN

Native VLAN — VLAN, кадры которого идут по транку **без тега**. Обе стороны транка должны иметь одинаковый native VLAN, иначе кадры попадут не в тот VLAN. Правило безопасности: native VLAN не должен использоваться рабочими хостами.

### Порты Access и Trunk

| Характеристика      | Access-порт                          | Trunk-порт                                   |
| ------------------- | ------------------------------------ | -------------------------------------------- |
| Сколько VLAN         | один                                 | много (до 4094)                              |
| Тегирование          | кадры без тега                       | все кадры с тегом, кроме native VLAN         |
| Куда подключают      | оконечные устройства (ПК, принтер, IP-телефон) | коммутаторы, роутеры, гипервизоры, АРМ с VLAN |
| Настройка            | `switchport mode access`             | `switchport mode trunk`                      |

<span style="color: 00cc18">Ключевые команды (Cisco):</span>

- `vlan 10` / `name OFFICE` — создать VLAN;
- `switchport mode access` + `switchport access vlan 10` — access-порт;
- `switchport mode trunk` + `switchport trunk allowed vlan 10,20,30` — транк с разрешёнными VLAN;
- `switchport trunk native vlan 99` — задать native VLAN;
- `show vlan brief`, `show interfaces trunk` — проверка.

<span style="color: 00cc18">Другие системы:</span>

- **MikroTik**: `/interface bridge vlan add bridge=bridge1 tagged=ether1 untagged=ether2 vlan-ids=10`; порт-транк — `tagged`, access — `untagged`;
- **Linux**: `bridge vlan add dev eth0 vid 10 pvid untagged` / `dev eth1 vid 10 tagged` (пакет `vlan`/`bridge`), интерфейс `eth0.10`.

На гипервизоре (Proxmox/VMware/Hyper-V) порт в режиме **trunk**, а нужный VLAN указывается у виртуального интерфейса VM (VLAN tag / bridge VLAN).

### Router-on-a-Stick (Inter-VLAN routing)

Маршрутизация между VLAN одним физическим интерфейсом роутера: интерфейс делится на **подынтерфейсы** (subinterfaces), каждый в своём VLAN и со своим шлюзом. Трафик идёт так:

```
ПК VLAN10 → access-порт коммутатора → trunk → subif роутера VLAN10
          → таблица маршрутизации → trunk → subif роутера VLAN20
          → access-порт коммутатора → ПК VLAN20
```

<span style="color: 00cc18">Ключевые команды (Cisco):</span>

- `interface gi0/0.10` — создать подынтерфейс;
- `encapsulation dot1Q 10` — привязать к VLAN 10 (тег);
- `ip address 192.168.10.1 255.255.255.0` — шлюз для этого VLAN;
- `encapsulation dot1Q 99 native` — native VLAN без тега;
- физический `interface gi0/0` оставляют без IP, `no shutdown`.

**Альтернатива — SVI (L3-коммутатор):** на коммутаторе включают маршрутизацию (`ip routing`) и поднимают SVI на каждом VLAN:

```
interface vlan10
 ip address 192.168.10.1 255.255.255.0
 ip routing
```

SVI быстрее (маршрутизация внутри ASIC) и «куда ноги не дойдут» на small-office с одним коммутатором. ROAS удобнее, когда коммутатор чистый L2.

#### Типичные ошибки на экзамене:

- не совпадает **native VLAN** на двух концах транка — кадры уходят в чужой VLAN;
- на транке не разрешили нужный VLAN (`allowed vlan`) — трафик молча дропается;
- подынтерфейс создали, но **не задали `encapsulation dot1Q <vid>`** — трафик не тегируется;
- на физическом интерфейсе роутера оставили IP — ломает схему ROAS;
- на коммутаторе забыли создать VLAN (`vlan 10`) — access-порт остаётся в VLAN 1;
- шлюз (SVI/subif) указан за пределами своей подсети, либо на ПК указан не тот шлюз;
- VLAN 1 используют как рабочий — безопасность и лишний широковещательный домен;
- путают access/trunk на стороне гипервизора: VM не поднимает VLAN.
