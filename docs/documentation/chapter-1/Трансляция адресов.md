# Трансляция адресов

NAT, PAT, SNAT, DNAT (проброс портов)
### Трансляция адресов (NAT)

NAT (Network Address Translation) — подмена IP-адресов и/или портов в заголовках пакетов на проходе через маршрутизатор. Зачем: экономия публичных адресов (приватные **RFC 1918** не маршрутизируются в интернете), сокрытие внутренней структуры сети, публикация внутренних сервисов.

| Приватный диапазон        | Префикс         |
| ------------------------- | --------------- |
| 10.0.0.0 – 10.255.255.255 | 10.0.0.0/8      |
| 172.16.0.0 – 172.31.255.255 | 172.16.0.0/12 |
| 192.168.0.0 – 192.168.255.255 | 192.168.0.0/16 |

Интерфейсы делят на **inside** (внутренняя сеть) и **outside** (внешняя). Трансляция срабатывает на границе.

### Виды NAT

| Вид          | Что делает                                        | Соотношение | Пример применения          |
| ------------ | -------------------------------------------------- | ----------- | -------------------------- |
| Static NAT   | жёстко «1 приватный ↔ 1 публичный»                 | 1:1         | публикация сервера          |
| Dynamic NAT  | берёт адрес из **пула** публичных                  | 1:1 временно | много хостов, много адресов |
| PAT / NAT overload | подменяет ещё и **порты**, many→one         | many:1      | выход в интернет из офиса   |
| SNAT         | подмена **источника** (source)                     | —           | исходящий трафик            |
| DNAT         | подмена **назначения** (destination)               | —           | проброс порта (port forwarding) |

**PAT** (он же NAT overload, на MikroTik — **masquerade**) — основной режим дома и в офисе: сотни хостов выходят наружу под одним публичным адресом, различаются по номерам портов.

### Таблица трансляций

NAT-устройство ведёт таблицу соответствий (в Linux — conntrack). Пример для выхода клиента:

| Inside (до)          | Outside (после)      |
| -------------------- | -------------------- |
| 192.168.1.10:51000   | 203.0.113.5:40001    |

Ответный пакет на `203.0.113.5:40001` разворачивается обратно к `192.168.1.10:51000`. Записи PAT живут по таймауту.

### Проброс портов (DNAT / port forwarding)

Внешний запрос на `публичный_IP:порт` подменяется на `внутренний_IP:порт`. Так публикуют веб, SSH, RDP:

```
203.0.113.5:8080  →  192.168.1.10:80
```

**Hairpin NAT** (NAT loopback) — случай, когда внутренний клиент обращается к внутреннему серверу по **публичному** адресу; нужен отдельный SNAT, иначе ответ пойдёт напрямую и соединение порвётся.

<span style="color: 00cc18">Ключевые команды:</span>

- **Linux (nftables)**: `nft add rule ip nat postrouting oifname "eth0" masquerade` (SNAT/PAT); `nft add rule ip nat prerouting tcp dport 8080 dnat to 192.168.1.10:80` (DNAT); просмотр — `conntrack -L` / `nft list ruleset`;
- **iptables**: `iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE`; `iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.10:80`;
- **Cisco**: интерфейсы `ip nat inside` / `ip nat outside`; PAT — `ip nat inside source list 1 interface gi0/0 overload` (ACL №1 задаёт внутренние сети); static — `ip nat inside source static 192.168.1.10 203.0.113.5`; проброс — `ip nat inside source static tcp 192.168.1.10 80 203.0.113.5 8080`;
- **MikroTik**: `/ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade`; проброс — `chain=dstnat dst-port=8080 protocol=tcp action=dst-nat to-addresses=192.168.1.10 to-ports=80`.

Включить **ip_forward** (`net.ipv4.ip_forward=1`) — без него Linux не пропускает чужие пакеты.

#### Типичные ошибки на экзамене:

- путают **SNAT** (источник) и **DNAT** (назначение) — правила ставят не в ту цепочку (`POSTROUTING` vs `PREROUTING`);
- забыли `sysctl net.ipv4.ip_forward=1` — маршрутизация между интерфейсами не работает;
- неверно помечены inside/outside на Cisco — NAT не срабатывает;
- публикуют сервер через DNAT, но не открывают порт в **файрволе** (filter) — трафик дропается;
- нет правила **hairpin NAT** — внутренние клиенты не видят сервер по внешнему адресу;
- пересекаются приватные диапазоны двух площадок за NAT — коллизия адресов;
- ожидают, что NAT защищает от вторжений — это не фильтр, а подмена адресов;
- PAT под высоким NAT-таймаутом «роняет» долгие сессии (или наоборот, слишком короткий таймаут рвёт idle-соединения).
