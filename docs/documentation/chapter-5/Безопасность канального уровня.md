# Безопасность канального уровня

port security, DHCP snooping, DAI, 802.1X
### Безопасность канального уровня

Атаки на L2 опасны тем, что происходят «внутри» сети и часто не видны на маршрутизаторе. Коммутатор нужно защищать отдельно.

### Основные атаки L2

| Атака              | Суть                                   |
| ------------------ | -------------------------------------- |
| MAC flooding       | переполнение CAM → коммутатор флудит   |
| MAC spoofing       | подмена MAC                            |
| ARP spoofing       | подмена ARP-ответов (MITM)             |
| DHCP starvation/rogue | захват/подставной DHCP-сервер       |
| VLAN hopping       | двойной тег (QinQ), перескок VLAN       |
| STP-манипуляции    | подставной root bridge                 |

### Механизмы защиты (Cisco)

- **Port Security** — ограничение числа MAC на порту, привязка к порту:
  - `switchport port-security`, `maximum 1`, `mac-address sticky`, `violation shutdown`;
- **DHCP Snooping** — доверенные (uplink, к DHCP-серверу) и недоверенные порты; отбрасывает ответы DHCP из недоверенных:
  - `ip dhcp snooping`, `ip dhcp snooping vlan 10`, `ip dhcp snooping trust`;
  - попутно строится **таблица привязок** MAC/IP/VLAN/порт;
- **Dynamic ARP Inspection (DAI)** — проверяет ARP по таблице snooping, блокирует подмену:
  - `ip arp inspection vlan 10`, trusted-порты;
- **IP Source Guard** — фильтрует по связке IP/MAC из таблицы;
- **BPDU Guard / Root Guard** — защита STP на абонентских портах;
- **Native VLAN** не VLAN 1 и не используется рабочими хостами; отключение автотранкинга (`switchport nonegotiate`);
- **802.1X** — аутентификация порта до выдачи доступа (RADIUS), гостевой/карантинный VLAN;
- неиспользуемые порты — `shutdown` и в «мёртвый» VLAN.

### Типичные ошибки на экзамене:

- uplink не помечен **trusted** при включённом DHCP snooping/DAI — сеть «ложится»;
- Port Security с `maximum 1` на порту, где нужен ещё IP-телефон/камера;
- DAI без таблицы snooping (не включён DHCP snooping) — не работает;
- native VLAN оставлен VLAN 1 и совпадает на всех — VLAN hopping;
- не отключён DTP (автотранкинг) на абонентских портах;
- 802.1X включён без fallback — гости/старое оборудование не подключаются;
- забыли про управление: SNMP community «public», telnet вместо SSH;
- неиспользуемые порты активны и в рабочем VLAN.
