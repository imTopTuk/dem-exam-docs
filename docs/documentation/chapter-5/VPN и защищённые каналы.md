# VPN и защищённые каналы

IPsec/IKEv2, WireGuard, OpenVPN, site-to-site и RA
### VPN и защищённые каналы

VPN (Virtual Private Network) создаёт **шифрованный туннель** через незащищённую сеть. Используется для связи площадок (site-to-site) и удалённого доступа сотрудников (remote access).

### Типы VPN

| Тип              | Для чего                                  |
| ---------------- | ----------------------------------------- |
| Site-to-site     | соединить две сети (офис ↔ филиал)        |
| Remote access (RA) | отдельный пользователь → корпоративная сеть |
| Client-to-site   | то же, что RA                              |
| Host-to-host     | связь двух узлов                           |

### IPsec

Набор протоколов на сетевом уровне (L3), «из коробки» защищает любой IP-трафик.

- **AH** — аутентификация/целостность (без шифрования);
- **ESP** — шифрование + аутентификация (основной);
- **режимы**: **Transport** (шифрует полезную нагрузку) и **Tunnel** (шифрует весь пакет, для site-to-site);
- **IKE/IKEv2** — обмен ключами и параметрами (порты UDP 500/4500);
- две фазы: **Phase 1** (ISAKMP SA, защита самого туннеля) и **Phase 2** (IPsec SA, защита трафика);
- параметры должны **совпадать** у сторон: шифр, хеш, DH-группа, PSK/сертификаты.

### WireGuard, OpenVPN

- **WireGuard** — современный, лёгкий, встроен в ядро Linux; конфиг — обмен **публичными ключами**; очень быстрый;
- **OpenVPN** — зрелый, на TLS (сертификаты), гибкий, кроссплатформенный; порт 1194;
- **L2TP/IPsec**, **SSTP**, **IKEv2** — часто для мобильных/Windows-клиентов;
- **SSL VPN** — доступ через браузер/клиент к конкретным приложениям.

### Аутентификация в VPN

- **PSK** — общий секрет (просто, но не масштабируется, риск при утечке);
- **сертификаты (PKI)** — лучше для масштаба и отзыва;
- **MFA** — второй фактор для удалённого доступа (обязательная практика);
- RBAC — какие ресурсы доступны после подключения.

### Типичные ошибки на экзамене:

- не совпадают параметры IKE/IPsec (шифр/хеш/DH) — туннель не поднимается;
- PSK слабый или один на всех — утечка = компромисс всех туннелей;
- нет **MFA** на удалённом доступе;
- VPN выпускает пользователя во всю сеть (flat access) вместо нужных сегментов;
- «забыли» про MTU/MSS в туннеле — крупные пакеты теряются;
- не настроен **D(ead) P(eer) D(etection)/keepalive** — висящие туннели;
- сертификаты без проверки отзыва (CRL/OCSP);
- VPN-сервер напрямую в интернете без фильтрации и обновлений.
