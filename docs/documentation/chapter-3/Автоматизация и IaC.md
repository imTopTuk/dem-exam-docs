# Автоматизация и IaC

bash/PowerShell, Ansible, CI/CD
### Автоматизация и IaC

Автоматизация заменяет ручные операции повторяемыми сценариями: меньше ошибок, быстрее и воспроизводимо. **IaC (Infrastructure as Code)** — описание инфраструктуры в файлах, а не «руками в консоли».

### Скрипты

- **bash**: переменные, условия, циклы, `for f in *.conf`, `$(...)`, `$?`, функции; `set -euo pipefail`;
- **PowerShell**: командлеты `Verb-Noun`, конвейер, `Get-Service`, `Where-Object`, `ForEach-Object`;
- cron/systemd timers — периодический запуск; Task Scheduler в Windows.

Правила скриптов: логировать действия, проверять коды возврата, поддерживать идемпотентность, хранить в **git**.

### Конфигурационное управление (Ansible)

**Ansible** — агентless (работает по SSH), описывает желаемое состояние в **playbook** (YAML).

```
- hosts: webservers
  become: true
  tasks:
    - name: install nginx
      package: { name: nginx, state: present }
    - name: start nginx
      service: { name: nginx, state: started, enabled: true }
```

- **inventory** — список хостов, **roles** — переиспользуемые наборы задач, **variables/templates** (Jinja2);
- **идемпотентность** — повторный запуск не меняет уже настроенное;
- альтернативы: **Puppet/Chef/SaltStack** (агентные).

### IaC для инфраструктуры

- **Terraform** — описание ВМ/сетей/облака в HCL, план → применение;
- **Packer** — сборка образов;
- **Docker/Compose/K8s** — IaC для приложений;
- состояние хранят в **git** (и в remote state для Terraform).

### CI/CD

- **CI (continuous integration)** — автосборка, тесты, линтеры при каждом изменении;
- **CD (delivery/deployment)** — автоматическая доставка в среду;
- инструменты: GitLab CI, Jenkins, GitHub Actions; артефакты и версии;
- **secrets** — только в защищённом хранилище, не в репозитории.

### Типичные ошибки на экзамене:

- секреты (пароли, ключи) лежат в открытом виде в репозитории/playbook;
- скрипты без проверок и логов — «сломалось, непонятно где»;
- нет идемпотентности — повторный запуск ломает систему;
- «автоматизация» без контроля версий — нельзя откатить;
- запуск playbook от root без `become`-разграничения;
- тестируют сразу в продакшене (нет staging);
- хранят Terraform state на локальной машине — конфликты и потери;
- автоматизируют то, что не понимают, — тиражируют ошибку на весь парк.
