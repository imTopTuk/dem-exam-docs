# Диагностика сети и анализ трафика

ping/traceroute/mtr, tcpdump, Wireshark, ss
### Диагностика сети и анализ трафика

Диагностику ведут **снизу вверх по OSI**: кабель/линк → IP/маршрут → порт/служба → приложение. От простого к сложному.

### Проверка доступности и пути

- `ping` — доступность и задержка/потери (ICMP);
- `traceroute`/`tracert` (**UDP/ICMP/TCP**) — путь по хопам;
- `mtr` — traceroute + ping в динамике (потери на каждом хопе);
- `arp -a` / `ip neigh` — таблица соседей (L2);
- `dig`/`nslookup` — разрешение имён.

### Просмотр интерфейсов, адресов и портов

<span style="color: 00cc18">Ключевые команды (Linux):</span>

- `ip a`, `ip -br a`, `ip r` — адреса и маршруты; старое — `ifconfig`/`route`;
- `ss -tlnp` / `ss -tunap` — слушающие порты и соединения (замена `netstat`);
- `ip -s link` — счётчики ошибок/дропов на интерфейсе;
- `lsof -i :443`, `lsof -p PID` — кто держит порт/файл;
- `iptables -L -n -v` / `nft list ruleset` — правила файрвола.

### Анализ трафика

- **tcpdump** — захват пакетов в консоли:
  - `tcpdump -i eth0 -nn port 53`;
  - `tcpdump -i any -w capture.pcap`;
  - фильтры по `host`, `port`, `tcp`, `icmp`;
- **Wireshark** / `tshark` — разбор `pcap`: TCP-ретрансмиссии, RST, DNS-задержки, TLS-хендшейк, ARP-конфликты;
- **tcpdump + tshark** полезны, когда на сервере нет графики.

### Проверка производительности

- `iperf3 -s` / `iperf3 -c host` — пропускная способность канала;
- `curl -v -o /dev/null -w "%{time_total}" URL` — время ответа сервиса;
- `tcping`/`nc -zv host port` — доступность TCP-порта (а не только ping).

### Типичные ошибки на экзамене:

- делают вывод по одному `ping`: он «прошёл», а служба стоит (ICMP открыт, порт закрыт) — нужен `nc`/`curl`;
- путают «нет маршрута» и «закрыт порт» — снижают уровень слоя;
- `ping` блокируется файрволом, а сервис жив — «узел недоступен» ошибочно;
- tcpdump запускают без фильтра на нагруженном интерфейсе — теряют пакеты/диск;
- смотрят счётчики интерфейса сразу после `ifconfig` без `clear` — путают старые ошибки;
- DNS-проблемы лечат на L3 — а это L7;
- не учитывают асимметрию трафика (маршрут «туда» и «обратно» разный);
- не сверяют время, шифруют/не расшифровывают TLS-заголовки.
