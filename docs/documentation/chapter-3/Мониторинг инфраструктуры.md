# Мониторинг инфраструктуры

Zabbix/Prometheus, SNMP, метрики, триггеры, алерты
### Мониторинг инфраструктуры

Мониторинг отвечает на вопросы «работает ли», «как быстро деградирует» и «что сломалось первым». Он собирает **метрики**, сравнивает с порогами (**триггеры**) и уведомляет (**алерты**).

Базовый набор метрик: доступность (`ping`, порт), CPU, RAM, диски (заполнение/IOPS), сеть (трафик, ошибки, задержка), сервисы (процессы, HTTP-код, очередь), логи.

### Способы сбора

| Способ        | Как работает                          | Пример |
| ------------- | ------------------------------------- | ------ |
| Агент         | установлен на узле, отдаёт метрики    | Zabbix agent, node_exporter |
| Agentless     | опрос по сети                         | SNMP, ICMP, HTTP-проверка |
| Push          | узел сам присылает данные              | Prometheus pushgateway, Syslog |
| Логи/события  | анализ сообщений                      | ELK, Loki |

### SNMP

**SNMP** — протокол управления сетевым оборудованием. Агент хранит объекты в **MIB**, опрашивается по OID.

| Версия | Особенность                    |
| ------ | ------------------------------ |
| v1/v2c | пароль-«сообщество» (community) в открытом виде |
| v3     | аутентификация и шифрование    |

- опрос: `snmpget -v2c -c public 192.168.1.1 1.3.6.1.2.1.1.3.0`, обход: `snmpwalk`;
- **traps** — оборудование само присылает события (link down, reboot);
- для экзамена: знать, что community — это секрет, а v3 предпочтительнее.

### Zabbix и Prometheus

- **Zabbix** — классика: сервер + агенты, шаблоны, триггеры, графики, веб-интерфейс, действия (email/telegram);
- **Prometheus** — pull-модель + `node_exporter`; запросы на **PromQL**; визуализация в **Grafana**; алерт-менеджер;
- **Grafana** — единые дашборды поверх разных источников.

<span style="color: 00cc18">Ключевые элементы:</span>

- метрика → **item**; условие → **trigger**; действие → **action**;
- «OK → Problem → OK» и **подтверждение (ack)** инцидента;
- шаблоны и **автообнаружение** (discovery) — чтобы не настраивать каждый узел вручную.

### Типичные ошибки на экзамене:

- мониторят только «вверх/вниз», без загрузки и трендов — авария приходит внезапно;
- порог без «гистерезиса» — алерты «дребезжат» на границе;
- SNMP-community `public`, доступный отовсюду — дыра;
- опрос по публичной сети без ограничений — нагрузка и утечка;
- мониторинг не мониторится (сам сервер без контроля);
- слишком частый опрос — перегрузка оборудования и сети;
- алерты без приоритета — «стена уведомлений», важное теряется;
- агент без нужных плагинов (check) — метрик нет, дашборд пустой.
