### Сбор и анализ логов

Логи — первичный источник при разборе инцидентов. Основные задачи: **централизованный сбор**, **хранение**, **поиск** и **реакция** на события.

### Локальные журналы Linux

- **journald** — журнал systemd: `journalctl`, `journalctl -u nginx`, `-f` (live), `--since "1 hour ago"`, `-p err` (только ошибки);
- постоянное хранение: `Storage=persistent` в `/etc/systemd/journald.conf`;
- файлы `/var/log/` — `syslog`/`messages`, `auth.log`/`secure`, `dpkg.log`, журналы служб;
- ограничение размера журнала: `SystemMaxUse`.

### Syslog и rsyslog

**Syslog** — стандарт передачи сообщений (UDP/TCP **514**, TLS **6514**), формат: `PRI, timestamp, host, app, message`; уровни важности:

| Уровень | Значение        |
| ------- | --------------- |
| 0       | emergency       |
| 1–2     | alert / critical |
| 3       | error           |
| 4       | warning         |
| 5–6     | notice / info   |
| 7       | debug           |

**rsyslog** (`/etc/rsyslog.conf`) собирает и **пересылает**: `*.* @logserver:514` (UDP) / `@@` (TCP). На сервере — приём и раскладка по файлам/каталогам.

```
# отправка на центральный сервер
*.* @@192.168.1.30:514
# хранить отдельно ошибки
*.err /var/log/errors.log
```

### Windows

- **Просмотр событий** (`eventvwr`): журналы System, Application, Security;
- **Windows Event Forwarding (WEF)** / агент — сбор на центральный сервер;
- в AD — журнал **Security** (вход, изменение объектов) обязателен для аудита.

### Ротация логов

Логи нельзя хранить вечно — их **ротируют**:

- `logrotate` (`/etc/logrotate.d/`): частота, число копий, сжатие, `create` с правами, `postrotate` (переоткрыть файл службы);
- пример: `nginx` лог → weekly, rotate 8, compress;
- Dropbox/лимиты диска — иначе лог «съест» раздел.

### Централизованный анализ (ELK/EFK, Loki)

- **Elasticsearch** — хранение и поиск; **Logstash/Fluentd/Filebeat** — сбор и парсинг; **Kibana** — визуализация;
- **Loki + Grafana** — облегчённая альтернатива;
- **поиск и алерты** по событиям (`failed password`, OOM, диск 100 %);
- общее время на всех узлах (NTP!) — иначе события не сопоставить.

### Типичные ошибки на экзамене:

- разное время на серверах — логи невозможно сопоставить (нет NTP);
- лог-сервер принимает syslog от всех (UDP/514) — подделка событий, нужен TLS/фильтр;
- нет ротации — переполнение `/var` и отказ служб;
- после ротации служба пишет в старый дескриптор (`copytruncate`/`postrotate` забыли);
- пересылают всё подряд (`*.*`) — шум, нагрузка на сеть/диск;
- не хранят Security-журнал — нельзя разобрать инцидент;
- логи доступны всем пользователям — утечка чувствительных данных;
- забыли про retention — старые логи и место на диске.
