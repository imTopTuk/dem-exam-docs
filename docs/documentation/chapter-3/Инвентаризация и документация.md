# Инвентаризация и документация

IP-план, схемы, кабельный журнал, CMDB
### Инвентаризация и документация

Без документации эксплуатация превращается в гадание: непонятно, что где стоит, какие IP заняты и куда идёт кабель. Документация должна быть **актуальной** и **доступной** тем, кому положено.

### Что документируют

| Документ          | Содержание                                  |
| ----------------- | ------------------------------------------- |
| IP-план           | подсети, VLAN, шлюзы, статические адреса     |
| Схема сети (L1/L2/L3) | физика, VLAN, маршрутизация, точки выхода |
| Кабельный журнал  | порт ↔ порт, маркировка, длина, тип кабеля   |
| Реестр оборудования | модель, серийный номер, гарантия, прошивка |
| Реестр ПО и лицензий | версии, ключи, срок поддержки             |
| Учётные записи и сервисные аккаунты | владельцы, права, срок |
| Пароли/секреты    | только в защищённом хранилище (Vault), не в wiki |

### CMDB

**CMDB** (Configuration Management Database) — база конфигурационных единиц и связей между ними (сервер → приложение → БД → сеть). Помогает оценить влияние сбоя и планировать изменения. Родственник — **ITIL-процессы** и **управление изменениями (Change Management)**.

### Инструменты

- схемы: draw.io, Visio, mermaid; в Obsidian — Excalidraw;
- учёт: GLPI, NetBox, OCS Inventory, Zabbix (активы);
- IPAM — учёт адресного пространства;
- версионирование документации в **git**/wiki с историей правок.

### Правила ведения

- единый формат маркировки (`SW1-Gi1/0/1 → SRV1-eth0`);
- изменения вносят **вместе** с правкой инфраструктуры, а не «потом»;
- указывают дату и автора изменения;
- регулярный пересмотр (раз в квартал/год);
- разграничение доступа: схема сети — сетевикам, секреты — отдельно.

### Типичные ошибки на экзамене:

- документация «нарисована один раз» и устарела;
- пароли и ключи лежат в общей wiki/схеме;
- нет кабельного журнала — при обрыве ищут «методом перебора»;
- IP-план не учитывает зарезервированные/свободные диапазоны — конфликты;
- схема не отражает L2 (VLAN, trunk) — диагностика вслепую;
- нет владельцев у сервисных учёток — «ничьи» права;
- документ доступен всем без разбора — утечка топологии;
- одно хранилище и нет бэкапа самой документации.
