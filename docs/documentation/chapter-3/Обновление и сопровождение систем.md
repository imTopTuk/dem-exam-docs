### Обновление и сопровождение систем

Регулярные обновления закрывают уязвимости и добавляют поддержку оборудования. Задача администратора — обновлять **управляемо**, а не «на живую».

### Источники обновлений

- **Linux**: `apt`/`dnf`, репозитории (`/etc/apt/sources.list`, `/etc/yum.repos.d/`); официальные и локальные зеркала;
- **Windows**: Windows Update, **WSUS**/Windows Server Update Services для централизованной выдачи;
- **СЗИ/ПАК** и отечественное ПО — обновляют из реестра/вендора;
- **прошивки** сетевого оборудования — по рекомендациям вендора, отдельно от ОС.

### Виды и порядок

| Вид         | Что содержит                       | Риск  |
| ----------- | ---------------------------------- | ----- |
| security    | только исправления безопасности    | низкий |
| bugfix      | исправления ошибок                 | средний |
| feature/upgrade | новые версии/функции           | высокий |

Порядок: тестовая среда → **пилотная группа** → продуктив. Перед обновлением — бэкап/снапшот, проверка места на диске, чтение release notes.

### Окно обслуживания

- согласованное **время простоя** (обновление ядра требует перезагрузки);
- уведомление пользователей, план **откатa** и критерии успеха;
- для критичных узлов — **rolling update** по одному или кластер с переключением нагрузки;
- **живое обновление** (kpatch/livepatch) — когда перезагрузка недопустима.

<span style="color: 00cc18">Ключевые команды:</span>

- `apt update && apt upgrade`, `dnf upgrade --refresh`, `dnf updateinfo list security`;
- перезагрузка: `systemctl reboot`, ядро: `uname -r` до/после;
- откат пакета: `dnf downgrade pkg`, `apt install pkg=version`;
- проверка зависимостей: `dnf check`, `apt --fix-broken install`.

### Откат и восстановление

- снапшот ВМ/тома перед обновлением — быстрый возврат;
- бэкап конфигов (`/etc`) и баз данных;
- **иммутабельные** подходы и канареечные развёртывания (canary);
- ведение журнала изменений (что, когда, кем).

### Типичные ошибки на экзамене:

- обновляют прод без бэкапа/снапшота — откатываться нечем;
- сразу ставят мажорный апгрейд без теста — ломают совместимость;
- обновляют в рабочие часы без окна — неожиданный простой;
- забывают про **перезагрузку** после обновления ядра;
- не читают release notes — пропускают несовместимости;
- отключают репозитории и обновляют из случайных `.deb/.rpm` — повреждение зависимостей;
- нет плана отката — «метод тыка»;
- обновляют всё сразу на всех узлах — массовая авария.
